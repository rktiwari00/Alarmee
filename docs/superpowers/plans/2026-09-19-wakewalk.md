# WakeWalk — Walk to Dismiss Alarm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-ready, consumer-grade Android alarm application (**WakeWalk**) that requires the user to physically get out of bed and walk a configurable number of steps before the alarm can be dismissed, with robust Android 12–15 exact alarm, foreground service, sensor, and Room persistence architecture.

**Architecture:** 
- **Domain Layer:** Pure Kotlin (zero Android/DI dependencies) implementing `StepAccumulator`, `MovementValidator` (anti-cheat gait/confidence heuristics), `EmergencyDismissalPolicy`, `ChallengeEngine`, and `AlarmTimeCalculator`.
- **Platform Layer:** `AlarmManager.setAlarmClock()` triggers `AlarmReceiver` (short-lived partial wake-lock), which launches `AlarmForegroundService` (FGS type: `health`). The service owns the active `WakeSession`, manages looping `USAGE_ALARM` audio, vibration, and `AndroidSensorAdapter` (hardware step counter/detector + accelerometer fallback).
- **Presentation Layer:** Two distinct activities: `MainActivity` (Compose + Navigation: Onboarding, Home, Create/Edit, Statistics, Settings) and `AlarmActivity` (dedicated lockscreen full-screen activity over lockscreen observing `WakeSessionRepository`).

**Tech Stack:** Kotlin 2.0+, Jetpack Compose, Material 3, Hilt 2.51+, Room 2.6+, DataStore Preferences, Coroutines & Flow, Android Gradle Plugin 8.5+, Java 17, targetSdk 35, minSdk 26.

## Global Constraints
- **Prime Invariant:** Alarm reliability takes precedence over all other features. A failure of the UI must never terminate the active alarm session, audio, sensor processing, or challenge state.
- **Service Ownership:** `AlarmForegroundService` owns the active session; `AlarmActivity` is strictly a presentation client.
- **Zero Android in Domain:** Domain logic (`domain/**`) must not import any `android.*` packages, enabling standard JVM unit testing without Robolectric.
- **Android 14/15 FGS:** Service declared with `android:foregroundServiceType="health"` requiring `FOREGROUND_SERVICE_HEALTH` and runtime `ACTIVITY_RECOGNITION`.
- **Exact Alarms:** Use `<uses-permission android:name="android.permission.USE_EXACT_ALARM" />` with `setAlarmClock()`.
- **No Indefinite WakeLock:** WakeLock held in `AlarmReceiver` only until `AlarmForegroundService` promotes to foreground (under 5 seconds); no continuous wake-locks.
- **One Active Session Policy:** Singleton row in `ActiveSessionEntity` (`singletonId = 1`). Atomic completion via `db.withTransaction`.
- **Sensors:** Hardware step sensor primary; accelerometer cadence & variance validation for anti-cheat; accelerometer peak-valley fallback if hardware sensor missing.
